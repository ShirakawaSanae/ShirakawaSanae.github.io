# OrangePi AI Pro 20T 单节点 K3s Server

> 状态：进行中。本文记录本次部署的命令、关键输出、配置决策和排查结果。
> 不记录 Wi-Fi 密码、SSH 私钥、K3s node token、kubeconfig 或其他凭据。

## 目标与边界

- 节点：OrangePi AI Pro 20T，Ubuntu 22.04，aarch64。
- 角色：单节点 `k3s server`（control plane、datastore、kubelet、container runtime 和普通工作负载均在此节点）。
- 未来：另一块鲲鹏 OrangePi 作为 `k3s agent` 加入；两节点不是高可用集群。
- 存储：当前根文件系统在 64 GB TF 卡；暂不运行模型训练或推理。后续接入 SSD 前不迁移 K3s 数据目录。
- NPU：`npu-smi` 存在持续硬件健康告警。本次仅搭建 CPU K3s，不安装 Ascend Device Plugin，也不将 NPU 暴露为 Kubernetes 可调度资源。

## 官方依据

- K3s 支持 arm64/aarch64；server 基线为 2 CPU 核和 2 GB 内存。
- K3s server 需要对未来 agent 开放 TCP 6443；默认 Flannel VXLAN 需要节点间 UDP 8472；metrics-server 使用 TCP 10250。
- K3s 官方建议 ARM 设备使用 SSD，因为 etcd 对写入敏感；TF 卡仅用于当前学习阶段。
- 单节点 K3s server 是可运行的完整 Kubernetes 集群；agent 将用 `K3S_URL` 和 `K3S_TOKEN` 注册。

```text
IP4.DNS[1]: 202.38.64.17
```

执行（只读）：

```bash
nmcli connection show nhpcc702
```

关键输出：

```text
connection.autoconnect: yes
ipv4.method: auto
DHCP4.OPTION: dhcp_lease_time = 86400
DHCP4.OPTION: dhcp_server_identifier = 192.168.50.1
DHCP4.OPTION: ip_address = 192.168.50.250
```

结论：当前 Wi-Fi 由 DHCP 分配地址。由于无法从开发板读取路由器 DHCP 地址池，本次若将主机改为静态地址，会沿用当前的 `192.168.50.250/24`、网关 `192.168.50.1` 和当前 DNS。后续应在路由器中按 Wi-Fi MAC 做 DHCP 保留，以避免潜在地址冲突。
